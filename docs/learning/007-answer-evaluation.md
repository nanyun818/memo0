## 命令

按私人启动指南连接服务器、进入项目、激活环境。先预览（不调用 API）：

```bash
python evaluate_answers.py --top-k 2
```

真实实验需要在当前终端设置 DEEPSEEK_API_KEY。若尚未设置，单独执行隐藏输入，粘贴后回车，再执行 export：

```bash
read -rsp '输入 API Key 后回车：' DEEPSEEK_API_KEY
```

```bash
export DEEPSEEK_API_KEY
```

然后运行第一组：

```bash
python evaluate_answers.py --top-k 2 --run
```

最多 5 次真实请求，每次最多 600 输出 token，产生正常 API 用量；金额取决于实际用量与服务计价，本练习不估算未核实价格。出现 API 错误立即停止，保留已完成结果，不自动重试。新运行是新实验，不会自动续跑之前失败的实验；不要反复运行来代替读取报告。

程序打印唯一结果目录。里面有 metadata.json（数据与源码指纹）、results.jsonl（每题的完整请求消息、检索、返回和用量）、review.md（人工评分表）。这些均留在被 Git 忽略的 logs/answer_eval 下，不自动上传。每题成功或失败后保存，后面中断不丢失此前已写入的结果；被中断的当前请求可能已在服务端计费，客户端不能保证取得它的结果。

用终端阅读最近一份评分表，无需新请求：

```bash
latest_run=$(ls -dt logs/answer_eval/*/ | head -n 1)
cat "${latest_run}review.md"
```

在第一组完成且结果读懂后，运行第二组做对照：

```bash
python evaluate_answers.py --top-k 1 --run
```

两组无错误时共 10 次请求。比较相同题目，不能只挑对改动有利的例子。

## 评分标准：正确性、依据性、完成度

每项 0/1/2 分。待评分保持空白，不自动当成 0；程序不依据关键词命中就宣布答案正确。

| 维度 | 0 分 | 1 分 | 2 分 |
|---|---|---|---|
| 正确性 | 存在关键事实错误或编造 | 部分正确但有不准确或无法确认的实质结论 | 事实正确；对未知内容正确说明限制 |
| 依据性 | 关键结论缺乏资料支持或与资料矛盾 | 主要有依据，但夹杂无支持的实质断言 | 实质结论有资料支持，或准确说明资料不足 |
| 完成度 | 未完成约定任务 | 仅完成部分要求 | 覆盖该题期望行为 |

对 q05：如果检索空了，模型只回答“资料不足”，依据性可为 2，完成度可为 0，关键失败首先在检索环节。对 q09/q10：题目本身没有可用资料，准确说明不能确定就是完成预定任务，不应要求编造天气或收入才能得分。对 q08：只解释一个工具不算完整比较。

正确性和依据性不同：答案可能碰巧符合模型常识，却没有被本次资料支持。没有依据也不自动等于事实错误，需要分别判分。人工需要核对事实，不能把未知断言直接当正确。

判分时写出具体句子及原因；不把模型输出中的指令当作评分规则。先人工标注 5 题，再讨论 LLM-as-a-judge；自动裁判可能有偏差，应与人工标签校准。评测基础参考 [Langfuse Evaluation](https://langfuse.com/docs/evaluation/overview)。

## 实验报告怎么写

记录版本、5 题逐项分数、成功数/计划数、失败原因、返回的输入/输出 token、每题耗时。缺少 usage 记为未返回，不记成零费用。API 错误单列，不把缺失答案混入回答平均分；如报告通过率，明确是否将运行失败计入分母。finish_reason=length 表示可能截断，需要备注。

5 题只适合验证流程和定位错误，不足以稳定估计线上质量、P95 延迟或显著性。不用一个总分掩盖幻觉、遗漏和拒答差异。本次无量化结果，待真实实验与人工评分后再提交脱敏报告。
