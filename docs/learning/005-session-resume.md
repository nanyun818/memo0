# 05：退出后仍能继续的命名会话

日期：2026-10-28。状态：AI 协助实现、离线验证；学习者真实续聊结果待提供。没有集成 Mem0。

## 学习目标与产品需求

用户退出程序后，希望重新打开同一个会话继续提问；主动换一个会话时，希望从空历史开始。以会话名称决定加载哪个文件，先为单用户命令行实现这个需求。

数据路径：会话名称 → 对应 JSON 文件 → history 列表 → messages → 模型 API → 回答 → 保存更新后的 history。

`--no-context` 只关闭本地资料检索，仍然传递会话历史。`--session` 才决定是否保存和恢复历史。不传 `--session` 时，保持原来进程内聊天的行为。

## 练习（约 25 分钟）

在服务器的项目目录、已激活虚拟环境且已设置 DEEPSEEK_API_KEY 的终端执行。若提示符是 `你：`，先输入 `/exit` 返回 shell。若提示缺少密钥，按 [02](002-model-api.md) 的隐藏输入流程设置，不把密钥写入脚本或提交。

```bash
python day2.py --chat --no-context --session whale
```

第一次使用应显示恢复 0 轮。在 `你：` 后输入：

```text
本次练习的项目代号是蓝鲸。请简短确认。
```

确认终端显示已保存 1 轮，再输入 `/exit`。重新运行相同命令，应该显示恢复 1 轮，然后提问：

```text
刚才的项目代号是什么？
```

预期回答包含“蓝鲸”，但以实际返回为准。退出后运行新会话：

```bash
python day2.py --chat --no-context --session fresh
```

如果 fresh 从未使用，应恢复 0 轮。问相同问题，观察是否说明缺少信息；即使偶然猜中也不能证明获取了旧会话，要结合恢复轮数和实际请求内容判断。重复实验请用新的会话名称。

这三次提问会真实调用 API 并产生用量。只启动、恢复历史或输入 `/exit` 不会调用模型。

## 读代码：把概念连起来

在 `day2.py` 搜索以下片段：

```python
path = session_path(ROOT, args.session) if args.session is not None else None
history = load_session(path) if path is not None else []
history = run_question(question, config, history, args)
save_session(path, history)
```

这些是相关步骤的摘录，并非可单独粘贴运行的完整代码。`run_question` 用 `build_messages` 加入历史，获得回答后返回旧历史、新问题、新答案。成功返回后再保存；API 失败不会把未完成的问答写入会话。

`session_store.py` 负责文件读写与检查：名称仅允许英文字母、数字、下划线、短横线；消息必须是交替出现的完整 user/assistant 问答；坏文件明确报错，不自动清空。写入临时文件完整成功后才替换旧文件。

## 验证与限制

- 离线检查模拟 API 响应，验证两次独立 main 调用之间恢复历史，以及新会话不包含旧消息。模拟响应不代表模型真实回答。
- 还检查非法会话名称、坏文件、写入替换失败保留旧数据、20 轮上限。与原有 API 检查合计 12 项。
- 学习者已验证上一块离线 save/load；本块真实模型续聊尚待截图或脱敏结果。
- 本实现每次运行最多 10 轮，每个命名会话总计最多 20 轮；上限是练习保护，不是精确 token 预算。仍需限制超长输入、压缩历史并设计预算，这是后续工程工作。
- 同一会话只在一个终端运行；尚无并发锁或用户认证。不同文件只是会话分开存储，不是生产级用户权限隔离。
- 会话文件保存在被 Git 忽略的 logs/sessions 下，文件没有加密。只用虚构练习内容，GitHub 发布代码、笔记和必要的脱敏结果。
- 持久化保存整个会话；长期记忆还要提取值得保留的事实、按问题检索、更新和删除。Mem0 学习会建立在这些区别上。
