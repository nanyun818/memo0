## 评谁，决定了PASS是什么意思

我们现在检查“裁判能不能识别错误”，不是希望六条故意混合的候选答案全部通过。

| 层次 | j02咖啡机样例 | 希望的结果 |
|---|---|---|
| 候选答案是否有依据 | 没有 | 不通过，score=0 |
| 裁判判分是否符合建议标签 | 实际不通过，建议也不通过 | 校准检查通过 |

核心逻辑是：

```python
actual_pass = False    # 从已保存的真实裁判结果读取
reference_pass = False  # 预先建议的标签，尚待独立复核
assert actual_pass == reference_pass
```

assert表达式为True，自动测试就通过；False等于False为True。所以候选答案不通过，可以意味着“裁判识别出错误”这项校准测试通过。相反，如果咖啡机答案被裁判判为True，此测试失败，提示检查误判。

## 一次评分，多次读取

真正调用DeepSeek的是lesson.py --run。下面的命令只读已经保存的最新报告，与版本对应的参考标签比较，不调用任何模型：

```bash
python -m unittest -v test_saved_verdicts
```

只运行过j02时，检查仅覆盖1条；不能说六条全部通过。新脚本还检查样例文件哈希、结果数量、重复ID、执行状态和分数/通过字段一致性。执行错误或部分结果会导致检查失败，不能冒充有效答案判分。它使用Python标准库unittest，是围绕DeepEval输出的离线校准检查，不是DeepEval内置语义指标。

这只是对保存记录的重复验证。修改Prompt或应用代码后，读旧报告无法证明新版本没有退步；真正的新版本回归需要固定题目/标准、运行新版本、取得新结果，再比较。模型调用可能波动，标准与题目更改也必须记录。
